# Narrow SECURITY DEFINER Functions for Per-Table Autovacuum Tuning

Even in PostgreSQL 17+, the predefined `pg_maintain` role grants `VACUUM`, `ANALYZE`, `REINDEX`, `CLUSTER`, `REFRESH MATERIALIZED VIEW`, and `LOCK TABLE`, but does not permit `ALTER TABLE ... SET (autovacuum_...)`, which strictly requires table ownership (`object_ownercheck`). Granting table ownership to `agent_exec` would violate least privilege by allowing `DROP TABLE` and unrestricted `SELECT`/`INSERT`/`UPDATE`/`DELETE` on user tables. Instead, per-table autovacuum tuning and reversion are exposed through narrow `SECURITY DEFINER` functions owned by `bluebox_owner` (`public.agent_set_autovacuum` and `public.agent_reset_autovacuum`) that validate and modify only whitelisted `autovacuum_*` storage parameters, with `EXECUTE` granted to `agent_exec`.
